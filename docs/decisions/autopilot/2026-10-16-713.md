## Decisions

### D1 — #715: tiers
- **Decided:** sonnet implementers with every judgement written into the brief; opus QA on all three slices because the work is a data-exposure control with migrations and permission-gated writes.
- **Basis:** CORE.md section 15 (tier up for authorization, migrations, data exposure); account memory (sonnet is the default cap for sub-agents)

### D2 — #715: inbound WhatsApp Assistant replies
- **Question:** QA found the redirect also caught the Assistant's replies to whoever messaged us, contradicting decision 8 in #713.
- **Decided:** added a second explicit exempt purpose `inbound_reply`, passed only at the two reply sites (`identity.ts`, `financial.ts`), enforced by a scan test, in the same PR.
- **Basis:** owner precedent (#713 decision 8)
- **Reversible by:** removing the purpose at those two call sites

### D3 — #716: guard trigger on the new column
- **Question:** the `authenticated` role has table-level UPDATE on all 37 `residents` columns and a resident can update their own row, so a resident could set their own `use_override_comms` to `false` and bypass the redirect.
- **Decided:** the migration includes a `BEFORE INSERT OR UPDATE` trigger: only `service_role`, a session with no JWT, or a user holding `settings.manage_general` may change the column (else `42501`). Measured first (read-only, then the trigger exercised on Stage inside a rolled-back transaction).
- **Basis:** owner precedent (#713 decision 2: only settings managers may change the flag). It only narrows access, so it is not on the park list.
- **Reversible by:** the migration's rollback block

### D4 — #717: Debug Mode semantics
- **Decided:** Debug Mode is effective only with an expiry that is present, parseable and in the future; a switch on with no expiry counts as expired; an unparseable expiry keeps the redirect on. The generic settings writers now validate the comms keys so Debug Mode cannot be kept on indefinitely through them.
- **Basis:** owner precedent (#713 decision 7); recommendation for the unparseable case (errs toward not leaking)

### D5 — #717: Debug & Testing tools kept
- **Decided:** after the first QA reported that replacing the old debug page removed "Send Test Email" and "Send Payment Reminders Now", the owner said both are important and must stay. `/settings/email/debug` was restored with only those two tools and notices.
- **Basis:** owner decision in the live session, 2026-10-16

### D6 — wiki pages
- **Decided:** `residents/add-and-assign-resident.md` was re-stamped by the #716 implementer after QA judged the reviewed content sufficient. `integrations/email-and-sms.md` was edited but NOT re-stamped: it is many commits behind its sources and needs a fuller review.
