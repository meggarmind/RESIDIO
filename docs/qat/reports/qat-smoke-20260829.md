## Method and a correction to it

The sweep was executed by parallel test agents, each in its own browser tab, using a 3-second settle wait per page. **That wait was too short.** Six pages were initially recorded as "not rendered / stuck loading" that in fact render correctly given 10–20 seconds on this dev server.

Every anomaly reported by an agent was therefore **re-verified directly with a 15–20 second wait before being recorded as a defect**. Four claimed failures did not survive that re-check and are listed under "Retracted" below rather than reported as bugs. The two that did survive are reproducible on demand and are filed.

This is worth stating plainly because it is the main methodological risk in a sweep of this kind: a slow page and a broken page look identical to a short timer.

## Defects

### QAT-SMK-D1 — System settings and System Health pages crash to an error boundary  [HIGH]

**Steps to reproduce**

1. Sign in as `super_admin`.
2. Navigate to `/settings/system` (or `/settings/system/health`).
3. Wait for load.

**Expected**

The System settings hub renders, including the cron job health card.

**Actual**

The page is replaced by the error boundary:

> Something went wrong
> Cannot read properties of undefined (reading 'overall')
> Try again · Dashboard

Console:

```
TypeError: Cannot read properties of undefined (reading 'overall')
The above error occurred in the <CronHealthCard> component.
It was handled by the <ErrorBoundaryHandler> error boundary.
```

Reproduced in a clean browser tab with a 20-second wait, on both routes.

**Root cause**

[src/components/dashboard/cron-health-card.tsx:152](src/components/dashboard/cron-health-card.tsx:152):

```ts
const overallStatus = data?.status || (data as { overall?: string }).overall || 'unknown';
const jobs = data?.jobs || [];
const lastChecked = data?.lastChecked || (data as { timestamp?: string }).timestamp;
```

The first term uses optional chaining (`data?.status`) and correctly yields `undefined` when the React Query result has no data. The **second term does not** — `(data as {...}).overall` dereferences `data` directly, so it throws the moment `data` is `undefined`. The `|| 'unknown'` fallback is unreachable.

Line 154 repeats the same unguarded pattern with `.timestamp`.

Note that the component gets this right elsewhere — [line 45](src/components/dashboard/cron-health-card.tsx:45) guards properly with `if (data && (data.status || data.overall) && ...)`. Only the render path is missing the guard.

**Why `data` is undefined here**

`/api/health/cron-status` builds its response with `createAdminClient()` and queries several tables. Whenever that query path fails or returns nothing, React Query yields `undefined` and the render throws. The component has loading and error branches above line 152, so the crash is specifically the "resolved but empty/failed payload" case.

**Impact**

Two admin pages are completely unreachable: the System settings hub and the System Health monitor. The System Health page is the tool an administrator would use to notice that cron jobs have stopped — so this defect disables exactly the monitoring surface that would reveal a related outage.

**Suspected fix**

Add optional chaining to both fallback terms at lines 152 and 154.

**GitHub issue**: [#106](https://github.com/meggarmind/RESIDIO/issues/106)
