# Release v1.11.0

**Release date:** 23 October 2026. **Release type:** Minor (new features, no upgrade steps).

## Summary

Billing now has a **Payer** setting on each billing profile. Security dues go to the occupant. Estate levies go to the landlord. A co-resident must now have a sponsor in the same house. The WhatsApp Assistant is better for people with several houses, for co-residents, and when WhatsApp is switched off. This release also closes several security and duplicate-message problems.

## New features

### Billing and invoices

- Each billing profile has a **Payer** field. You can see and change it in **Settings > Billing > Billing Profiles**.
- Security dues go to the occupant: the tenant, or else the resident landlord. A vacant house bills the non-resident landlord.
- A house that is flagged as new and never occupied gets no dues while it is vacant.
- Estate levies, such as the Development Fee, go to a landlord and never to a tenant.

### Residents

- Every active co-resident must have a sponsor. The sponsor is the resident landlord or the tenant of the same house. The app now enforces this rule.

### WhatsApp

- The Assistant works only for people who have an active residency in a supported role. Other people get one polite reply, at most once in 24 hours.
- A person with several houses can choose **All my properties**. The reply shows one line for each house and a total. Each line names the charge type, for example security dues or a levy.
- The wallet label is **Wallet (all your properties)** for people with several houses. Only occupants can ask for a clearance certificate.
- A co-resident now sees the financial menu of the sponsor's house. This includes what is owed, recent payments, statements, receipts and payment reports.
- A sponsor can create a LINK code for a co-resident inside the Assistant. The co-resident can then link a number without the estate office.
- When the WhatsApp master switch is off, the Assistant sends one holding reply. When you switch it on again, the Assistant answers the saved messages. It drops a saved message that is older than 24 hours.
- A message that a daily or burst limit holds back now sends automatically at the next window. This applies to clearance certificates and approval results.
- The statement period list hides **All time** when it is the same as **Since move-in**.
- The **Recent payments** list is numbered.
- A resident can end a chat session with an exit word: exit, end, close, bye, goodbye or quit.
- The admin help reply now lists the **ADMIN DEBT** command. It emails a debt status report for the estate or for chosen streets.

## Changes

### WhatsApp

- The daily message limit now resets at midnight in Lagos. It reset at 01:00 before.
- WhatsApp messages and template fields show dates as dd mmm yyyy, for example 31 Aug 2026.
- A number that sends wrong LINK codes too many times is locked for a short time.

### Settings

- The settings navigation now fits the visible screen at 100% zoom.

### Resident portal

- The wallet top-up button is hidden. The top-up flow cannot work yet.

## Fixed problems

### Payments and reminders

- Payment reminders no longer go out twice when the daily job runs two times.
- The app now reports a failed read of reminder data as a failure.
- A payment made between 00:00 and 01:00 Lagos time now has the correct date.

### Billing and invoices

- Two quick clicks no longer add a late fee two times to one invoice.
- Two one-time levies for the same house on the same day now get different numbers.

### Imports

- A bank statement upload now skips lines that the app already stored. It tells you how many lines it skipped. Before, the whole upload failed.
- Email imports now match residents by phone number.
- Email imports now read the account number from PDF statements.

### WhatsApp

- Clearance certificates and approval results now obey the master switch, the pilot audience and the daily limits.

### Security and access

- Only admins who manage settings can add, replace or remove the estate logo.
- An admin can no longer edit the record of their own impersonation session.
- Visitor pass images now need a valid signed link.
- The sign-up email check gives the same answer whether or not an email is registered.
- The two-factor feature no longer uses a fixed fallback secret outside production.

## Behind the scenes

- This release removed unused software libraries, unused files and unreachable code.
- Tests and the admin guide build were updated.
