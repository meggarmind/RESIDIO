# Release v1.9.0

**Release date:** 21 October 2026. **Release type:** Minor (new features). Operator steps are necessary: see **Before you upgrade**.

## Summary

This release changes the WhatsApp assistant a lot. It has a new menu, a PIN with a lockout, a privacy notice, and statements that always arrive as a PDF. Settings has fewer pages, a search field, and one **Roles & Access** page. Admins can verify payments in bulk, set up recipient groups, and edit the wording of resident messages. The release also makes access rules stricter, and speeds up several admin pages.

## Before you upgrade

Make sure the database changes of this release are applied before you use the new features. An operator must also do these steps.

1. Check that the Prod settings `NEXT_PUBLIC_SITE_URL` and `NEXT_PUBLIC_APP_URL` each hold the Prod app address. Use https and no slash at the end.
2. After the release, save the privacy notice text and a new version label in the WhatsApp settings. The public privacy policy page ships with this release.

## New features

### WhatsApp assistant

- The assistant has a new menu with two levels. It is named "Residio Assistant".
- The assistant asks a resident to confirm identity and accept a privacy notice before it shows any record. The app keeps the notice version that the resident accepted.
- A resident must have a PIN. The estate office gives the resident a setup code, and the resident then sets the PIN in the chat. The assistant refuses weak PINs and lets the resident change the PIN.
- The PIN locks for 15 minutes after 3 wrong tries. It stays locked after 6 wrong tries in 24 hours, until the estate office resets it.
- In the WhatsApp console, an admin can issue a link code, issue a setup code, and reset a PIN.
- A resident can turn payment reminders on or off, change the email address after a code check, and report a payment from the assistant.
- Every statement is a PDF. The assistant no longer sends statement text. A new **Since move-in** period starts the statement on the day the tenancy began.
- The assistant asks for a rating after a successful request. It asks for the reason when the rating is poor.
- When the assistant says what is due, it now looks at every unpaid invoice. Before, it could say that nothing was due.
- A shared account balance can reach residents through an admin switch. The switch is off by default.
- The assistant reads the privacy notice from the chat text. It fills in the estate name and the site address.

### Settings

- The Settings sidebar has a search field. It finds single settings and not only pages.
- Settings pages are merged by task. These are the new pages:
  - **Reminders**, **Message Wording**, **Email & Sending** and **Announcements**.
  - **Estate Profile** (details, logo, theme) and **Streets & Houses**.
  - **Billing Rules** and **Banking**.
  - **Documents** and **Security Rules**. Session timeout is now in **Security Rules**.
  - **Maintenance & Data**.
- Each section has its own Save and Discard buttons. It shows "Unsaved changes" or "Saved". The page asks before you leave with unsaved changes.
- The Settings start page has a setup checklist and groups pages by task.
- A new **Debt Status** page lets an admin edit the status labels and the threshold. One shared rule now decides Arrears, Outstanding, Paid in Full and Credit.
- A new **Monitoring** link in Settings opens the audit logs and other System pages.

### Roles and access

- **Settings > Roles & Access** is one page for administrators, pending sign-ups, unlinked logins and roles. It replaces the two older pages. The old addresses still open it.
- An admin can give a role and a title together, for example Vice Chairman under the chairman role. A title can have a seat limit, and the page shows who holds a seat.
- The role model has changed. New roles are Welfare Officer, Trustee and Security Guard Supervisor. The roles Vice Chairman, Project Manager and Resident no longer exist. Titles replace Vice Chairman.
- A resident admin role needs a linked resident.
- Read-only roles, such as Trustee, no longer see action buttons.
- The app now uses permissions, not a role rank, to decide who may change whose account.

### Groups

- **Settings > Groups** lets an admin make named lists of residents. Messages and copies can go to a list. Clearance certificate copies use it first.

### Payments

- An admin can verify many payments at once from the **Payments** list. A new permission, payments.verify, controls this.
- The audit log now shows the payment reference for verify and unverify entries.

### Messages and notifications

- **Settings > Message Wording** lets an admin edit the wording of five resident emails: welcome, payment receipt, payment reminder, escalating reminder and new invoice. An empty field uses the built-in text.
- An admin can also edit the WhatsApp wording of payment reminders and payment receipts.
- An admin chooses the channels for the payment receipt, the welcome message and the new-invoice message.
- The Reminder Schedule step editor now offers WhatsApp.
- **System > Notification queue** lists every WhatsApp message that the app sends, also the assistant replies.
- The app records the delivery status of each WhatsApp send. It alerts admins about failed sends and sends with no confirmation.
- The app finds inbound WhatsApp messages that the webhook missed.
- A banner shows in the app while maintenance mode or the communications override is on.

### Residents

- When an admin creates a resident, the app looks for a resident that already exists. It offers to link the new house to that resident.

### Houses

- The house detail page is split into smaller parts. It loads only the data that you ask for, and it fits a phone screen.

### Public pages

- The app has a public privacy policy page at /privacy-policy.

## Changes

### Dashboard

- The command board on the dashboard shows fewer items and loads faster.
- The Estate Assistant widget no longer shows on the sign-in screens.

### Residents

- The resident detail page has fewer tabs. Write controls show only to users with the permission, and the page fits a phone screen.
- Move out, Transfer and Remove assignment now use the app confirmation dialog.

### Expenditure

- The expense ledger loads one page at a time from the server. Cancel and Mark as Paid ask for confirmation, and write controls follow permissions.

### Settings

- Write controls on Settings pages show only to users with the matching permission. Controls are larger on a phone.
- Each Settings area now checks its own permission when you save. Before, some areas opened for an admin but refused the save.
- Some wrong or old text in Settings is corrected. This includes the reminder timing text and old phase notes.
- The audit-log retention setting now takes effect, and data retention can prune audit logs.
- A WhatsApp or Chatmaid from-number must be a paired phone. It must not be the same as the communications override WhatsApp number.

### Billing and wallets

- The yearly wallet ledger now loads in pages. Long wallet histories are no longer cut off.
- Bulk work is faster for bank statement import, levy generation and wallet allocation.
- Late fees now have a lasting marker on the invoice item. Before, the app found them by the item text.

### Access rules

- Database access rules use permissions, not role names. Signed-in users see no change.
- Visitors who are not signed in can read and change nothing on the tables that this release re-scoped.
- Database rules now check which roles an admin may grant. Functions that return visitor and occupier contact details now check the caller permission.

## Fixed problems

- Repeated WhatsApp reply text is no longer dropped as a duplicate.
- WhatsApp links to an old phone number now stop when a resident changes the phone number. The app checks the roster and the account status again.
- WhatsApp delivery status that arrives early is retried. Before, some sends stayed pending.
- The WhatsApp retention job accepts periods that the settings page saves as text. It also purges survey answers and outbound send records after 90 days.
- Resident statements now include rows from the last day of the period. Day limits use Lagos time.
- The scheduled payment reminders use the billing reminder days and the email switch from Settings.
- The first save of a reminder schedule now creates the schedule. Errors now show on the page.
- Scheduled announcements now publish without a user session.
- The scheduled email import now runs. It queues every transaction for admin review and can open password-protected statement PDFs.
- The email-import actions and the reminder run no longer accept calls from users with no permission.
- The Log Expense dialog now shows the reason when a save fails.
- The sidebar menu now scrolls on a short screen. The footer is reachable.
- House short names are now safe for invoices. A name with a space gets a hyphen.

## Behind the scenes

- The release adds a speed test for the admin dashboard and lists. It also adds checks for the database backup, and the backup now removes old deleted files and uses the PostgreSQL 17 client.
- Many wiki pages and project documents now match the app.
