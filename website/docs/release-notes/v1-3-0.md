# Release v1.3.0

**Release date:** 15 October 2026. **Release type:** Minor (new features). Operator steps are necessary: see **Before you upgrade**.

## Summary

This release adds a control rule to bank statement imports: the person who submits an import cannot approve it. The daily invoice job now follows the automatic generation switch and the generation day. This release also fixes three display problems.

## Before you upgrade

1. Apply the database change for the import submitter record to Residio_Prod before the deploy. The new code fails closed if the change is missing.
2. Automatic invoice generation is off on Residio_Prod. Switch it on when the estate goes live. If you do not, you must generate the first month by hand.
3. On Residio_Stage, the first scheduled run creates a real October generation run. The run does not allocate wallet credit, send resident emails or add late fees.

## New features

### Payments and imports

- The app now records who submits a bank statement import for approval. The person who submitted an import cannot approve it.

### Billing and invoices

- The daily backup job for invoice generation is now active on Stage and Production. It runs every day at 07:00 UTC.

## Changes

### Billing and invoices

- The daily invoice job now follows the automatic generation switch and the generation day that you set in the settings. Before, it ignored changes to both values.

### System

- The **Cron Status** card no longer shows a false Critical state when automatic invoice generation is off. It now shows "Automatic generation is off".

## Fixed problems

- Statement dates in imports now stay on the correct calendar day. Before, an import made east of UTC (for example, in Nigeria) could show the day before the real date.
- The **Invoice Aging** card on the analytics page now shows a loading state while it loads. If it cannot load, it shows "Invoice aging unavailable". Before, it showed "No overdue invoices." in both cases.

## Behind the scenes

- The check that compares the Production database with the migration files now allows for the way Production was first built.
