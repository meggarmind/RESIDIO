# Release v2.0.0

**Release date:** 24 October 2026. **Release type:** Major (upgrade steps are necessary).

## Summary

Residents are now grouped by role: Landlords, Non-Resident Landlords, Owner-Occupiers and Tenants. Announcements can target these groups and show how many people they reach before you send. The WhatsApp Assistant has a simpler Financial menu. This release needs two database changes on production.

## Before you upgrade

1. Apply these two database migrations to the production database, in this order. Apply them one at a time.
   - `20261101090000_resident_role_view_and_groups.sql`
   - `20261101100000_announcement_target_group.sql`
2. Record each migration in the production migration list under the exact version in its file name.
3. Run the migration drift check on production after the last migration.
4. Deploy the release after both migrations are applied.

Both migrations are already applied on the stage database.

## New features

### Residents

- Residents are now grouped by role. A person with more than one role counts in each role. The groups are Landlords, Non-Resident Landlords, Owner-Occupiers and Tenants.
- The app can count residents for each role and for each group. You do not need a manual database query for role counts.

### Announcements

- An announcement can now target a resident group. A person who is in more than one group receives the announcement once.
- Before you send, the form shows how many people the announcement will reach and how many of them have a WhatsApp opt-in.

### WhatsApp

- In the resident WhatsApp Assistant, **Link a co-resident** is now item 8 on the Financial menu. It shows only to the resident landlord or tenant of the selected property. It disappears when a co-resident on that property has linked their WhatsApp.
- The **More** menu is removed. **Switch property** is now item 10 on the Financial menu, for residents who are billed for more than one property.

## Changes

- The version label in the sidebar for a stage build now shows a single version number with a "-dev" ending, for example v1.0.341-dev. Release builds do not change.

## Fixed problems

- **Announcements:** WhatsApp delivery of an announcement sent nothing when you chose an audience by role. The system also gave no error. It now reads the role correctly and records any read error.
- **Payment reminders:** The **Send payment reminders** switch showed a success message but did not save. It now saves, and it shows an error if the save fails.
- **Dashboard:** The browser window could scroll past the bottom of the admin dashboard into empty space. The page no longer scrolls. Only the main area scrolls.

## Behind the scenes

- Issue labels and board status now change automatically from development events. A nightly check corrects any difference.
- The stage environment is now built as an image in the automated pipeline and deployed on each push. The old stage deploy path is removed.
- Release tags are now checked, and the instruction files for agents were updated.
