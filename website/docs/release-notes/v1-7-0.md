# Release v1.7.0

**Release date:** 16 October 2026. **Release type:** Minor (new features). Operator steps are necessary: see **Before you upgrade**.

## Summary

This release adds a communications override. It sends outgoing email, SMS and WhatsApp messages to test contacts instead of the real recipients. You can use it on Stage, and on Production in Debug Mode. Debug Mode now works for all three channels and it expires by itself.

## Before you upgrade

1. Apply three database changes to Residio_Prod before the deploy. Until the resident setting exists, every message to a resident fails.
2. Make sure the Production build has the application environment set to production. If the value is missing or unknown, the app treats the system as non-production. It then redirects messages, or blocks them if the override contacts are blank.
3. After the deploy, check that the sidebar shows no STAGE or DEV badge.
4. Send one test email from **Settings > Email > Debug & Testing**.
5. On Stage, set the override email and phone in **Settings > Communications override**. Then check one run of the payment reminders and notifications jobs.
6. After the database changes, regenerate the database types.

## New features

### Settings

- The new **Communications override** settings page sets the override email and phone. It also has the global override switch.
- The override works when the app sends a message. It covers email, SMS and WhatsApp. Each redirected message shows the name of the original recipient.
- A message is blocked, not sent, when the override contact is blank or invalid, or when the app cannot read the settings. The app never sends it to the real address in these cases.
- Two kinds of message are not redirected: two-factor sign-in codes and replies from the WhatsApp Assistant to inbound messages.
- Outside production, the redirect is always on. In production, the override does nothing until you switch it on.

### Residents

- Each resident now has a setting for the override. The choices are: follow the environment default, use the override, or send to the real recipient.
- Only users who can manage general settings can change this setting. A resident cannot change it.

### Debug Mode

- Debug Mode now redirects messages on all channels. Before, it only skipped emails.
- Debug Mode has an expiry time from 5 to 480 minutes. If it is on and has no expiry time, it counts as expired.
- You cannot switch Debug Mode on while the override email or phone is blank or invalid. The app writes each change to the audit log.
- Debug Mode overrides a resident setting of "send to the real recipient".
- The **Send Test Email** and **Send Payment Reminders Now** tools stay on the **Settings > Email > Debug & Testing** page.

## Known behavior

- The **Send Payment Reminders Now** tool shows "No invoices due for reminders today" when a blank override email blocks all sends. This matters only on Stage.

## Behind the scenes

- The repository now has a pre-commit check that finds secrets in staged changes.
- The release updates development tool versions to remove security warnings, and adds a weekly update schedule for dependencies.
