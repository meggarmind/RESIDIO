## What ships, by area

**Reports** (parent #1396, still open)
- Reports foundation: one permission per report, summary-first layout, more report types can be scheduled (#1397).
- Debtors and aging: one report replaces Debtors and Invoice Aging (#1399).
- Dues, levies and collection status, with a Charge setting (#1400); the Indebtedness Detail report can now be generated (#1379).
- Collection rate by street, expenses by category and vendor, wallet balances (#1403).
- Statement of account for one house or one resident (#1402).
- Project spend and petty cash (#1404).
- Budgets screen and Budget against actual report (#1406).
- Indebtedness Report names the dues payer, not the first linked resident (#1420).
- Reports read every row, not only the first 1,000, so totals are complete (#1419).

**Billing and invoicing**
- Dues write-off for settlements: Write off bills dialog, Written off status, Write-offs report. Only super_admin and chairman get the permission (#1460).
- The monthly invoice cron finishes the whole run, not one 50-house chunk a day (#1450).
- New indexes make invoice reads faster (#1439).

**Payments and bank imports**
- Approve a bank alert as one or more dues/levy types; adds the Toll Gate Levy and Other charges (#1443).
- Awaiting verification page and a live count of queued payments (#1432).
- A checked FirstBank alert counts as bank proof on the dashboard and on WhatsApp (#1428).
- Email imports: stat cards filter the list; full-width clickable rows (#1427).
- FirstBank "Ref" is read only as a whole-word label (#1359).

**WhatsApp admin tools and assistant** (parent #1290, still open)
- Admin tools item 6, Unverified payments, and an unverified line in Today's collections (#1424, #1422).
- Item 6 finds the house by resident name (#1433).
- Admin tools code is asked for once a day (#1410).
- Resident status: short lines with code and icon (#1393), matching houses listed with resident names (#1445), finds a resident by payer alias (#1452).
- Paid up status shows the months the last payment paid (#1408); Cleared shows the next payment due (#1385); the answer and the hint go as two messages (#1387).
- The receipt sent during Report a payment is kept; admins can View receipt (#1455).

**Sign-in security (two-factor)** (parent #1388, still open)
- Approve admin sign-ins on WhatsApp (#1389).
- Remember this computer for 30 days (#1390).
- Two-factor SMS codes are not sent while SMS is switched off (#1464).

**SMS**
- HollaTags as a second SMS provider, chosen in Settings → Email & sending (#1462).

**Residents and houses**
- Merge residents: likely duplicates first, then inline search (#1391).
- Residents table hides archived residents by default (#1395).
- Shared house-tile grid for the estate map, occupancy and dues views (#1398).
- Resident names are stored in capitals (#1414).

**Expenses**
- The mock Scan a receipt button is removed (#1454).

**Operations and housekeeping**
- Time limits on outside calls (SMS, Paystack, WhatsApp send) (#1438).
- db-backup fails when a prune listing fails (#1338).
- TODO.md retired: GitHub issues are the backlog (#1456).
- Dependency bumps, minor and patch (#1426).

## Pending Prod migrations (apply in this order after merge; each needs the owner's word)
All nine are applied on Residio_Stage (checked by name, 8 Nov 2026). Flags: **RBAC** = adds or grants permissions; **auth** = touches sign-in or `auth.*`; **RLS** = row-level security or grants.

- [ ] `supabase/migrations/20261106090000_two_factor_whatsapp_approval.sql` — **auth, RLS**: new `two_factor_whatsapp_requests` table (RLS on, service_role only, anon/authenticated revoked); `approve_sign_ins` column on `whatsapp_admin_bindings`.
- [ ] `supabase/migrations/20261106100000_residents_uppercase_names.sql` — trigger plus backfill to capitals. **One-way data change**: a rollback cannot restore the previous casing.
- [ ] `supabase/migrations/20261107090000_two_factor_trusted_devices.sql` — **auth, RLS**: new `two_factor_trusted_devices` table (service_role only); revoke triggers on `auth.users` (password change) and `public.profiles` (role or two-factor change). Apply before the app deploy.
- [ ] `supabase/migrations/20261107095000_drop_report_type_checks.sql` — drops the `report_type` CHECK constraints on `generated_reports` and `report_schedules` (Stage ledger holds it as `20261102153948 drop_report_type_checks`; it pairs by name).
- [ ] `supabase/migrations/20261107100000_whatsapp_admin_unverified_payments.sql` — **RBAC**: new permission `whatsapp_admin.unverified_payments`, granted to chairman, financial_officer, super_admin.
- [ ] `supabase/migrations/20261107110000_debt_status_charge_category.sql` — **RLS (grants)**: `get_debt_statuses` re-created with an optional third argument; EXECUTE revoked from PUBLIC/anon, granted to authenticated and service_role as before; SECURITY INVOKER.
- [ ] `supabase/migrations/20261107120000_invoice_read_indexes.sql` — five indexes on `invoices` / `invoice_items`; no table, policy or function change.
- [ ] `supabase/migrations/20261107130000_charge_categories_toll_gate_other.sql` — two charge categories, `toll_gate_levy` and `other`.
- [ ] `supabase/migrations/20261107140000_invoice_write_offs.sql` — **RBAC, RLS**: new permission `billing.write_off_invoices` (super_admin and chairman only); `invoice_write_offs` table; SECURITY DEFINER `write_off_invoices` / `undo_invoice_write_off` that check the permission inside.

Verify each by name in the Residio_Prod applied-migration list (CORE.md §11).

Set them on `residio-prod` only if Prod will use HollaTags; the provider is chosen in Settings → Email & sending.
