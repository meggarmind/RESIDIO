# Release v1.1.0

**Release date:** 15 October 2026. **Release type:** Minor (new features). Operator steps are necessary: see **Before you upgrade**.

## Summary

This release limits who can read private data, such as private documents, estate settings and verification codes. It adds an approval screen for bank statement imports. Failed notifications now retry by themselves. The dashboard also shows a live status strip and no longer shows a failed section as zero.

## Before you upgrade

1. Check the production environment. The container now stops at start-up if a necessary variable is missing or wrong.
2. Make sure these variables are set: the Supabase URL, the Supabase anon key, the Supabase service role key, and `CRON_SECRET`.
3. Set `NEXT_PUBLIC_ENV_MODE` to `cloud`. If you do not set it, the app uses `local` and reads the `_LOCAL` variable names.
4. Apply the 14 new database migrations to the production database in version order. Start with `20261014100000_revoke_truncate_from_api_roles`. End with `20261015100000_drop_verification_tokens_resident_select`.
5. Apply the migrations before the production deploy. Check each one by name against the list of applied migrations.

Missing optional services, such as Resend, Paystack, Termii, Google and WhatsApp, cause a warning only.

## New features

### Payments and imports

- A new approval screen for bank statement imports. Open an import from **Import History** (under Payments) to see its details and approve or reject it. Imports now need approval before they are processed.
- The notification "Bank Import Awaiting Approval" now opens the import. Before this release, its link led to a missing page.

### Approvals

- An approval that was approved but not applied can now be applied again. Before this release, such a request stayed stuck.
- Each request type now has its own checks when the approval is applied. The system also records the result in the audit log.

### Dashboard

- A live status strip at the top of the admin dashboard. It changes with the time of day. It shows the items that need attention, unverified payments, and the latest activity.
- Moving from the residents list to a resident now has a smooth transition. It does not run when the browser or the user setting asks for less motion.

### Notifications and WhatsApp

- A failed notification send now retries when the error is temporary. The retry waits 15 minutes, then 1 hour, 6 hours and 24 hours. The app does not retry errors that can not succeed, such as a missing phone number.
- Staff now get a notification when a renter starts a move-out. The notification goes to the security officers and the financial officers.

### Administration

- A new system action log records what automatic processes did, such as scheduled jobs and webhooks. Only super admins can see it. This release adds the log and the permission. It does not add a screen to read the log.
- The audit log now records the change when a bank import changes status.

### Reports

- Scheduled reports now run by themselves. Before this release, they could not run, because they needed a signed-in user.

## Changes

### Security and access

- Private documents and their files now show only to the linked resident and to users who can edit documents. Users who can only view documents, such as security officers, no longer see private documents.
- A new version of a private document now stays private.
- Users now need the permission to view documents to get a document link.
- Estate settings now show only to users with the settings permission. A short list of public settings, such as the estate name and logo, stay open to all signed-in users.
- Eight more data lists, which any signed-in user could read before, now follow the same rule.
- The email imports storage, which holds bank statements and payment evidence, now needs the permission to view email imports. Secretaries and security officers lose read access.
- Receipt download now needs the permission to view payments, or the user must own the invoice. Finance and other payments roles can now download receipts.
- Financial officers can now see and approve requests in **Approvals**. Before this release, the app allowed it but the database blocked it.
- A resident can no longer read their own contact verification code. A code now stops working after 5 wrong tries, and the user must ask for a new code.
- The app no longer shows the list of staff to users who do not have permission.
- The app removed the option to make new backup codes without a second-factor check.
- Bank statement passwords are no longer open to any signed-in user.
- Anonymous users lose the rights to run wallet functions and to empty tables.
- Flagging and clearing a flag on a security log still use the permission to view security logs. Clearing a flag is now recorded in the audit log, with the earlier flag state.

### Audit

- Ten admin actions that did not write to the audit log now do so.
- The audit log now stores the correct record for 23 more actions. Before this release, the app did not save these entries.

### Notifications and WhatsApp

- The WhatsApp master switch now also stops incoming WhatsApp handling and replies. Before this release, it stopped only outgoing messages.
- SMS sending is off for now. The app checks the WhatsApp opt-in when it queues a message.

### Imports

- A bank import can now move only from one valid status to the next. If two users change the same import at the same time, the second user sees "Import status changed, please refresh and try again".
- On the email import page, the Process and Skip buttons show only to users with the permission to process. A failed load now shows an error, not an empty list. The search box, which did not work, is removed. The Unmatched count can no longer be negative.

### Dashboard and menus

- A section of the dashboard that fails to load now shows "unavailable". Before this release, it showed zero, such as "All clear" or "No invoices".
- The mobile menu now shows the nested items. Import Statement, Import Email, Generate Invoices, Generate Reports and Financial Overview were missing before.
- The sidebar build label is shorter, for example `v1.0.0+341`. Hover over it to see the full version.
- The role names now match on all admin screens: Property Owner, Owner-Occupier, Renter and Occupant.

## Fixed problems

### Residents

- The owner and renter move-out wizards now work. Before this release, they always stopped with "Resident not found".

### Billing and invoices

- The backup invoice job can now catch up later in the month if it missed its day. A cancelled run is not made again.
- The status of the invoice job now comes from the real runs.
- The daily backup invoice job no longer fails when its settings are missing. The job now skips that environment and sends an email that names the missing settings.

### Reports

- The report schedule can no longer be started by a client request.

## Known problems

- On the analytics page, **Invoice Aging** shows "No overdue invoices." if its own data load fails.

## Behind the scenes

- The app now checks its environment at start-up and stops at once if a necessary setting is missing.
- The database has nightly encrypted backups for production and weekly backups for stage. The database also has faster security rules and fewer duplicate indexes.
- The release checks now fail on two migrations with the same version number, and the build no longer needs a placeholder key.
